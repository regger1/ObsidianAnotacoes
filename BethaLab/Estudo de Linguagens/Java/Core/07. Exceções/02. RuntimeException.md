# Try-Catch em Java - Checked Exceptions

## O que e uma Exception

Uma exception e um evento inesperado que acontece durante a execucao do programa. Em vez de o programa simplesmente quebrar, o Java te da ferramentas para **tratar** esse erro e decidir o que fazer quando ele acontece.

---

## A estrutura do try-catch

```java
try {
    // codigo que pode dar erro
} catch (TipoDaException e) {
    // o que fazer quando o erro acontece
}
```

- **try**: voce coloca dentro dele o trecho de codigo que pode lancar uma exception. O sistema vai **tentar** executar esse bloco normalmente.
- **catch**: se uma exception do tipo especificado for lancada dentro do `try`, a execucao pula direto para o `catch`. Ali voce decide como tratar o erro.

O fluxo e simples:
1. O codigo dentro do `try` comeca a rodar linha por linha.
2. Se nenhum erro acontecer, o `catch` e completamente ignorado.
3. Se um erro acontecer, o Java para a execucao do `try` naquele ponto e pula direto pro `catch`.

---

## Checked vs Unchecked Exceptions

O Java divide exceptions em dois grandes grupos:

| Tipo | Obriga try-catch? | Exemplo |
|---|---|---|
| **Checked** | Sim, o compilador exige que voce trate | `IOException`, `SQLException`, `FileNotFoundException` |
| **Unchecked (Runtime)** | Nao, o compilador nao obriga | `NullPointerException`, `ArrayIndexOutOfBoundsException` |

**Checked exceptions** sao erros que o Java considera previsiveis. Por exemplo: voce esta tentando criar um arquivo, mas o diretorio pode nao existir. O compilador sabe que isso pode acontecer e te obriga a tratar com try-catch (ou declarar com `throws`).

**Unchecked exceptions** sao erros de logica do programador, como acessar uma posicao que nao existe em um array. O compilador nao te obriga a tratar, mas elas ainda podem acontecer em tempo de execucao.

---

## Exemplo pratico

```java
private static void criarNovoArquivo() {
    File file = new File("Java-Estudos/arquivo/teste.txt");
    try {
        boolean isCriado = file.createNewFile();
        System.out.println("Arquivo Criado: " + isCriado);
    } catch (IOException e) {
        e.printStackTrace();
    }
}
```

O metodo `createNewFile()` lanca uma `IOException` (checked exception). Isso significa que o compilador nao deixa voce usar esse metodo sem um try-catch. Se algo der errado, como o diretorio nao existir, a exception e capturada pelo catch.

---

## O metodo printStackTrace()

```java
catch (IOException e) {
    e.printStackTrace();
}
```

O `printStackTrace()` imprime no console toda a **pilha de chamadas** (stack trace) que levou ate o erro. Isso inclui:
- O tipo da exception e a mensagem de erro
- O arquivo e a linha exata onde o erro aconteceu
- A sequencia de metodos que foram chamados ate chegar ali

Exemplo de saida:

```
java.io.IOException: Arquivo ou diretorio inexistente
    at java.io.File.createNewFile(File.java:1045)
    at ExceptionTest01.criarNovoArquivo(ExceptionTest01.java:14)
    at ExceptionTest01.main(ExceptionTest01.java:8)
```

Voce le de baixo para cima: o `main` chamou o `criarNovoArquivo`, que chamou o `createNewFile`, que lancou a exception.

---

## Por que nunca deixar o catch vazio

```java
// ERRADO - nunca faca isso
catch (IOException e) {
}
```

Se o bloco do catch estiver vazio, a exception acontece e e simplesmente engolida. O programa continua rodando como se nada tivesse acontecido, mas o arquivo nao foi criado. Voce nao vai ter nenhuma informacao sobre o que deu errado, o que torna a depuracao muito mais dificil.

No minimo, use `e.printStackTrace()` para registrar o erro.

---

## Resumo

- `try` envolve o codigo que pode falhar.
- `catch` captura um tipo especifico de exception e permite tratar o erro.
- Checked exceptions (como `IOException`) obrigam o uso de try-catch.
- `printStackTrace()` mostra o rastreamento completo do erro.
- Nunca deixe o bloco catch vazio.
