## O que é

A partir do Java 7, e possivel capturar **mais de um tipo de excecao no mesmo bloco `catch`**, separando os tipos com o operador pipe `|`. Isso se chama **multi-catch**.

Serve para quando voce quer tratar exceções diferentes da mesma forma, sem precisar repetir o mesmo codigo em varios blocos `catch`.

---
## Sintaxe
```java

try {

// codigo que pode lancar excecoes

} catch (TipoExcecao1 | TipoExcecao2 | TipoExcecao3 e) {

// tratamento unico para todas elas

e.printStackTrace();

}

```

A variavel `e` e compartilhada entre todos os tipos listados. Voce so declara uma vez.

---
## Exemplo pratico

Sem multi-catch (repetitivo):
```java

try {

talvezLanceException();

} catch (SQLException e) {

e.printStackTrace();

} catch (FileNotFoundException e) {

e.printStackTrace();

}

```

  
Com multi-catch (limpo):
```java

try {

talvezLanceException();

} catch (SQLException | FileNotFoundException e) {

e.printStackTrace();

}

```

O comportamento e identico nos dois casos. A diferenca e que o multi-catch elimina a duplicacao de codigo.

---
## Regras importantes

### 1. As excecoes nao podem ter relacao de heranca entre si

Voce **nao pode** colocar no mesmo multi-catch uma excecao pai e uma excecao filha. O compilador vai reclamar.

```java

// ERRO DE COMPILACAO

// IndexOutOfBoundsException é pai de ArrayIndexOutOfBoundsException

catch (IndexOutOfBoundsException | ArrayIndexOutOfBoundsException e) {

// nao compila

}

```

Isso acontece porque se voce ja esta capturando a excecao pai, a filha ja estaria coberta. Seria redundante.

### 2. A variavel do catch e implicitamente final

Dentro de um multi-catch, a variavel `e` e tratada como `final`. Voce **nao pode reatribui-la**.

```java

catch (SQLException | FileNotFoundException e) {

e = new SQLException(); // ERRO DE COMPILACAO

}

```

Em um catch normal (com um tipo so), voce consegue reatribuir. No multi-catch, nao.

### 3. O tipo da variavel e a uniao dos tipos

O compilador trata `e` como sendo do tipo mais especifico que e ancestral comum de todas as excecoes listadas. Na pratica, voce so consegue chamar metodos que existem em todos os tipos listados (ou seja, os metodos de `Exception`/`Throwable`).


---

## Quando usar

- Quando voce quer **tratar excecoes diferentes da mesma forma** (mesmo log, mesmo `printStackTrace`, mesma mensagem).

- E melhor do que capturar diretamente `Exception` ou `RuntimeException`, porque o multi-catch e **explicito** sobre quais excecoes voce esta tratando. Capturar `Exception` pega tudo, inclusive excecoes que voce nao esperava.

## Quando nao usar

- Quando cada excecao precisa de um tratamento diferente. Nesse caso, use blocos `catch` separados.

- Quando as excecoes estao na mesma hierarquia de heranca. Capture apenas a mais generica.
