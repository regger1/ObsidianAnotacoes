
## O que é

O **try-with-resources** e uma estrutura introduzida no Java 7 que **fecha automaticamente** recursos (como arquivos, conexoes de banco, streams) ao final do bloco `try`, sem precisar de um bloco `finally` manual.

Qualquer objeto que implemente a interface `AutoCloseable` (ou `Closeable`, que herda de `AutoCloseable`) pode ser usado dentro do try-with-resources.

---
## O problema que ele resolve


Antes do Java 7, fechar recursos era responsabilidade do programador. O codigo ficava verboso e propenso a erros:
```java

public static void lerArquivo() {

Reader reader = null;

try {

reader = new BufferedReader(new FileReader("teste.txt"));

// usa o reader...

} catch (FileNotFoundException e) {

e.printStackTrace();

} finally {

try {

if (reader != null) {

reader.close();

}

} catch (Exception e) {

e.printStackTrace();

}

}

}

```


Problemas desse approach:

- Voce precisa de um `finally` so pra fechar o recurso.
- Dentro do `finally`, precisa de outro `try-catch` porque o `close()` tambem pode lancar excecao.
- Se voce esquece de fechar, tem vazamento de recurso (memory leak, file handle leak).
- O codigo fica poluido e dificil de ler.

---
## Sintaxe

```java

try (TipoRecurso recurso = new TipoRecurso()) {

// usa o recurso

} catch (Exception e) {

e.printStackTrace();

}

// o recurso ja foi fechado automaticamente aqui

```

O recurso e declarado **dentro dos parenteses** do `try`. Ao sair do bloco (seja normalmente ou por excecao), o Java chama `close()` automaticamente.

---
## Exemplo pratico

Com try-with-resources (limpo):

```java

public static void lerArquivo() {

try (BufferedReader reader = new BufferedReader(new FileReader("teste.txt"))) {

String linha = reader.readLine();

System.out.println(linha);

} catch (IOException e) {

e.printStackTrace();

}

// reader.close() ja foi chamado automaticamente

}

```

Compare com o exemplo anterior sem try-with-resources. O codigo faz a mesma coisa, mas e muito mais curto e seguro.

## Multiplos recursos

Voce pode declarar **mais de um recurso** no mesmo `try`, separando por ponto e virgula `;`.

```java

try (Leitor1 leitor1 = new Leitor1();

Leitor2 leitor2 = new Leitor2()) {

  

// usa leitor1 e leitor2...

  

} catch (IOException e) {

e.printStackTrace();

}

```

Os recursos sao fechados na **ordem inversa** da declaracao. No exemplo acima, `leitor2` e fechado primeiro, depois `leitor1`. Isso e importante porque recursos declarados depois podem depender dos anteriores.

---
## Como criar uma classe compativel

Para usar sua propria classe no try-with-resources, ela precisa implementar `Closeable` ou `AutoCloseable`:

```java

public class Leitor1 implements Closeable {

@Override

public void close() throws IOException {

System.out.println("Fechando leitor1");

}

}

```

A diferenca entre as duas interfaces:

| Interface | Metodo | Excecao |

|---|---|---|

| `AutoCloseable` | `close()` | Lanca `Exception` |

| `Closeable` | `close()` | Lanca `IOException` |

`Closeable` estende `AutoCloseable`. Na pratica, se voce esta lidando com I/O, use `Closeable`. Para outros recursos, use `AutoCloseable`.

## Regras e detalhes

### 1. O recurso so existe dentro do bloco try

A variavel declarada nos parenteses do `try` nao e acessivel fora dele.

```java

try (BufferedReader reader = new BufferedReader(new FileReader("teste.txt"))) {

// reader acessivel aqui

}

// reader NAO acessivel aqui

```

### 2. O close() e chamado ANTES do catch e do finally

A ordem de execucao e:

1. Bloco `try` termina (normalmente ou por excecao)
2. `close()` e chamado automaticamente
3. Bloco `catch` executa (se houve excecao)
4. Bloco `finally` executa (se existir)
### 3. Suppressed exceptions

Se o bloco `try` lanca uma excecao E o `close()` tambem lanca outra excecao, a excecao do `close()` nao e perdida. Ela e adicionada como **suppressed exception** na excecao original.


```java

try {

// lanca ExcecaoA

} // close() lanca ExcecaoB

catch (Exception e) {

// e = ExcecaoA

// e.getSuppressed() contem ExcecaoB

Throwable[] suprimidas = e.getSuppressed();

}

```

Isso e uma vantagem sobre o `finally` manual, onde a excecao do `close()` simplesmente substituia a excecao original (voce perdia a informacao).
### 4. O catch e o finally sao opcionais

Diferente do `try` normal, no try-with-resources voce **nao precisa** de `catch` nem de `finally`. O `try` sozinho com o recurso ja e valido:

```java

try (MinhaConexao conn = new MinhaConexao()) {

// usa a conexao

}

// valido, sem catch nem finally

```
